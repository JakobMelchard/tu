# 08 How to write the protocol

The grade is the protocol [S1, S2]. TISS says nothing else: no length, no
template, no presentation, no weighting. So the protocol has to stand alone as
the evidence for 250 h of work, readable by a lecturer who did not watch it
happen. This note is the structure, the statistics and the reproducibility
standard; [`protocol_template.md`](protocol_template.md) is the skeleton to copy.

Code: [`../src/py/error_bars.py`](../src/py/error_bars.py).

## 1 What the reader must be able to check

1. **What question** was asked, and why it matters for the physics (one paragraph).
2. **What was done**, precisely enough to redo it: equations, algorithms, parameters.
3. **That the code is right**: validation against closed forms and libraries.
4. **What came out**, with uncertainties and a baseline.
5. **What it means and what it does not**: limitations, failures, next steps.

Every section below serves one of these.

## 2 Structure

| section | content | typical length |
|---|---|---|
| Title page | course 138.129, semester, supervisor, author, date, repository URL + commit hash | 1 p |
| Abstract | question, method, main number with error, one-line conclusion | 5 sentences |
| 1 Introduction | physics context, what is compressed / predicted and why, prior work [cited], the project's precise question | 1-2 p |
| 2 Theory and methods | definitions and derivations the results rest on (e.g. SVE of the kernel, note 03; TT-SVD error identity, note 05); algorithms as numbered steps | 3-6 p |
| 3 Implementation and validation | code layout, dependencies, **tests against closed forms** (single pole, Onsager, sklearn), convergence in discretisation parameters | 2-3 p |
| 4 Results | figures and tables with error bars and a baseline; each figure has one message stated in its caption | 4-8 p |
| 5 Discussion | agreement with expectation, limitations, what failed and why | 1-2 p |
| 6 Conclusion and outlook | answer to the question in 1, next step | 0.5 p |
| References | every claim not derived here | |
| Appendix | reproducibility: environment, seeds, commands, runtimes, data location | 1 p |

Page counts are our guess (no TISS guidance); agree length and language with
the supervisor at the topic meeting (note 00).

## 3 Error bars

**Independent repetitions** (seeds, independent Markov chains, noise draws):
$\bar x\pm s/\sqrt n$, $s^2=\frac1{n-1}\sum(x_i-\bar x)^2$ (`mean_sem`). Five seeds
of a training run are the minimum for an ML number.

**Correlated series** (one Markov chain, a time series): the variance of the mean
is $\operatorname{var}\bar x=\frac{\sigma^2}{n}2\tau_{\rm int}$,
$\tau_{\rm int}=\tfrac12+\sum_{t\ge1}\rho(t)$. **Binning**: average blocks of length
$b$; the naive error of the block means rises with $b$ and plateaus at the true error
once $b\gg\tau_{\rm int}$ (`binning_error`, `binning_curve`). Worked example
(`python error_bars.py`): AR(1) with $\rho=0.9$, $\tau_{\rm int}=(1+\rho)/(2(1-\rho))=9.5$,
$n=2^{16}$: naive error $3.9\times10^{-3}$, binned plateau $1.7\times10^{-2}$ =
exact $\sqrt{2\tau_{\rm int}/n}$. The naive error is $4.4\times$ too small.

**Derived quantities** (a crossing temperature, a fitted exponent, a median):
bootstrap over independent units (`bootstrap`); resample chains or seeds, never
correlated samples individually.

**Reporting.** One or two significant digits of error, value rounded to match:
$0.964\pm0.007$ or $0.964(7)$. Log-scale error plots: error bars are asymmetric;
plot the spread over seeds as a band or show all seeds as thin lines.

## 4 Figures that carry a compression or ML project

- **Error vs compression** (rank, bond dimension, bits, latent size) on log-$y$,
  with the baseline (uniform grid, PCA, TT-SVD optimum) in the same panel.
  Example: note 03's IR vs uniform grid (26 numbers vs 32768 points at $6\times10^{-9}$).
- **Train and test** curves together (note 04: MLP-AE train 0.37 vs test 0.62 is
  the finding, not a footnote).
- **Singular value spectra** $s_l/s_0$ on log scale: the physics of compressibility
  in one plot (notes 02, 03, 05).
- **Parameter dependence**: $\Lambda$, $L$, noise level $\sigma$, sample size $n$.
- For inverse problems: reconstruction vs truth, and the $m$- and $\alpha$-dependence.

Caption rule: what is plotted, parameters, number of seeds, what the error band is,
and the one conclusion.

## 5 Code and data availability

- Public (or supervisor-visible) git repository; the protocol cites a **tag or
  commit hash**. Licence file (MIT for code is the norm around sparse-ir [S14]).
- Pinned environment (`pyproject.toml` + lock file, or `requirements.txt` with versions).
- One command per figure (`make fig3` or `python scripts/fig3.py`), writing to
  `results/` with the git hash in the metadata.
- Seeds fixed and listed; runtimes and hardware stated.
- Data: generated by script (as everything in `../src`) or archived with a DOI
  (Zenodo) if large or expensive (QMC data from w2dynamics runs, say).
- Tests (`pytest`) that pin the validation claims of section 3.
- Ask the supervisor whether code review is part of the grading and what their
  policy on AI assistants is; declare tool use in the protocol either way.

## 6 Pitfalls

- A results section without a baseline: "error $10^{-4}$" means nothing alone.
- One seed. Neural-network numbers vary by more than the differences claimed.
- Errors from correlated samples treated as independent (section 3).
- Tuning hyperparameters on the test set, then reporting test error.
- Hiding failed approaches: a documented negative result (note 04, Ising) is
  part of 250 h of work and shows understanding.
- Code in the protocol body. Put it in the repository; show equations and pseudocode.
- Figures from notebooks with hidden state: regenerate every figure from a clean
  checkout before submission.

## 7 Questions

1. **The grade is "Protocol". What must the protocol contain so that it can be
   graded without a presentation?** Question, reproducible methods, validation of
   the code, results with uncertainties and baselines, honest discussion, and a
   pointer to code and data at a fixed commit (sections 1-5).
2. **You have 10^5 Monte Carlo snapshots from one chain. How do you quote the
   error of their mean?** Binning analysis: the plateau of the block-mean error,
   equal to $\sigma\sqrt{2\tau_{\rm int}/n}$; the naive $\sigma/\sqrt n$ is too small
   by $\sqrt{2\tau_{\rm int}}$.
3. **How do you put an error bar on a $T_c$ from a classifier crossing?**
   Independent datasets or training seeds, bootstrap over them; add the systematic
   finite-size shift by repeating at several $L$ (note 07).
4. **What makes a compression figure convincing?** Log-scale error vs cost, the
   baseline in the same panel, error bands over seeds, the parameter that controls
   compressibility varied, and a caption stating the conclusion.
5. **What belongs in the appendix rather than the main text?** Environment,
   commands, seeds, runtimes, hyperparameter tables, additional convergence checks;
   the main text keeps equations, validation and the figures that answer the question.
