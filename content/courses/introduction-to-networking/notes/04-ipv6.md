# 04 IPv6 (RFC 8200, STD 86)

> **Sourcing.** The header is RFC 8200, the addressing architecture RFC 4291,
> Neighbor Discovery RFC 4861, SLAAC RFC 4862, text representation RFC 5952,
> ULAs RFC 4193, /127 links RFC 6164, RA DNS options RFC 8106, stable and
> temporary IIDs RFC 7217 / 8981, Happy Eyeballs RFC 8305, Ethernet
> encapsulation RFC 2464 — all vendored [S13], [S15], [S17]. Section map:
> [`../refs/standards-map.md`](../refs/standards-map.md).

## Why and what changed

128-bit addresses ($3.4 \cdot 10^{38}$) end address scarcity and NAT; the header was simplified for fast forwarding; ARP and broadcast were replaced by multicast-based Neighbor Discovery; fragmentation moved to the sender; autoconfiguration is built in. Everything else (TCP, UDP, DNS, applications) is unchanged except for the address type — IPv6 is a new *network layer*, not a new Internet.

## Header (fixed 40 bytes) — RFC 8200 §3 [S13]

| Offset | Field | Bits | Notes vs IPv4 |
|---|---|---|---|
| 0 | Version | 4 | 6 |
| 0 | Traffic Class | 8 | = DSCP + ECN |
| 1 | Flow Label | 20 | per-flow tag for ECMP hashing / QoS, set by the source |
| 4 | Payload Length | 16 | **excludes** the 40-byte header (IPv4 Total Length includes it) |
| 6 | Next Header | 8 | same numbers as IPv4 Protocol (6 TCP, 17 UDP, 58 ICMPv6) or an extension header (0 hop-by-hop, 43 routing, 44 fragment, 50 ESP, 60 destination options) |
| 7 | Hop Limit | 8 | = TTL |
| 8 | Source | 128 | |
| 24 | Destination | 128 | |

Gone: IHL (fixed length), header checksum (link-layer CRC + transport checksum suffice; **the UDP checksum is mandatory over IPv6**, RFC 8200 §8.1 [S13]), fragmentation fields (moved to an extension header), options (extension headers form a chain: IPv6 hdr → hop-by-hop → routing → fragment → … → TCP, RFC 8200 §4). Routers process only hop-by-hop options. Minimum link MTU **1280**, RFC 8200 §5; routers **never fragment**: a too-big packet is dropped with ICMPv6 Packet Too Big (type 2), so PMTUD is mandatory and filtering ICMPv6 breaks IPv6.

## Address notation and types — RFC 4291 §2 [S13], RFC 5952 [S15]

Eight groups of 16 bits in hex, separated by `:`; leading zeros in a group may be dropped; **one** run of zero groups may be written `::` (RFC 4291 §2.2). RFC 5952 §4.2.2 then narrows the choice for *output*: use `::` for the **longest** run of zero groups, and on a tie the **leftmost**; never for a single zero group; lower-case hex. `2001:0db8:0000:0000:0000:0000:0000:0001` → `2001:db8::1`. In URLs: `http://[2001:db8::1]:8080/`. Prefix notation as in CIDR: `2001:db8::/32`.

| Type | Prefix | Scope / use |
|---|---|---|
| Global unicast | 2000::/3 | public; typical customer delegation /48 or /56, a LAN is a **/64** |
| Link-local | fe80::/10 (in practice fe80::/64) | mandatory on every interface, never routed; used by NDP, routing protocols, default-gateway addresses (`fe80::1%eth0` — zone index needed because every link has the same prefix) |
| Unique local (ULA) | fc00::/7 (fd00::/8 in use) | private, like RFC 1918; random 40-bit global ID (RFC 4193 §3 [S15]) |
| Multicast | ff00::/8 | ff02::1 all nodes on link, ff02::2 all routers, **solicited-node** ff02::1:ff00:0/104 + the target's low 24 bits (RFC 4291 §2.7.1) |
| Loopback | ::1/128 | |
| Unspecified | ::/128 | source before an address exists (DAD, DHCPv6) |
| IPv4-mapped | ::ffff:a.b.c.d | dual-stack sockets representing IPv4 peers |
| Anycast | any unicast address assigned to several nodes | routing delivers to the nearest; used for DNS root servers |

**No broadcast.** Anything IPv4 did with broadcast uses a multicast group.

The 64-bit **interface identifier** (IID) is the host part: from the MAC via modified EUI-64 (RFC 4291 Appendix A [S13] — insert `ff:fe` between the OUI and the device part, then **invert the universal/local bit**: `02:00:00:00:00:01` → IID `0:ff:fe00:1`; deprecated for privacy), random-but-stable per prefix (RFC 7217 §5 [S15]), or temporary **privacy addresses** (RFC 8981 §3.3 [S15], rotated daily; what your laptop uses for outgoing connections).

## Neighbor Discovery (NDP, RFC 4861 [S13]) replaces ARP and more

All messages are ICMPv6 (Next Header 58), sent with **Hop Limit 255**, and a receiver MUST discard anything arriving with a lower hop limit (RFC 4861 §3.1, §11.2) — a router would have decremented it, so 255 proves the packet was not forwarded. That single check is the whole of NDP's off-link protection, and it is the one structural improvement over ARP, which has no equivalent.

| Message | Type | Replaces / does |
|---|---|---|
| Router Solicitation (RS) | 133 | host asks for routers, to ff02::2 |
| Router Advertisement (RA) | 134 | router announces prefixes, MTU, default router lifetime, flags (M: use DHCPv6 for addresses, O: DHCPv6 for other info, A on prefix: autoconfigure), periodically and on RS, to ff02::1 |
| Neighbor Solicitation (NS) | 135 | = ARP request; sent to the target's **solicited-node multicast** ff02::1:ff + last 24 bits of the target address (so only ~1 host processes it, not everybody as with broadcast) |
| Neighbor Advertisement (NA) | 136 | = ARP reply (unicast); also unsolicited to announce a change |
| Redirect | 137 | = ICMP redirect |

**Neighbor cache** states: INCOMPLETE → REACHABLE → STALE → DELAY → PROBE (RFC 4861 §7.3.2 [S13]; Neighbor Unreachability Detection uses upper-layer hints or unicast NS to revalidate — ARP has nothing comparable).

**SLAAC** (stateless address autoconfiguration, RFC 4862 §5.3–5.5 [S13]): (1) form link-local fe80::IID; (2) **Duplicate Address Detection** (§5.4): NS for your own tentative address, sent *from the unspecified source* `::` because you have no address yet; if an NA comes back the address is taken; (3) send RS; (4) for every RA prefix with the A flag, form prefix::IID and run DAD again; (5) install default route to the RA's link-local source. DNS server: the RDNSS option in the RA (RFC 8106 §5 [S15]) or stateless DHCPv6 (O flag). Stateful DHCPv6 (M flag) is the alternative when the operator wants to control addresses; it does **not** hand out the default gateway (that always comes from RAs, RFC 4861 §6.3.4).

Spoofing carries over: rogue RAs (defence: RA Guard on switches, 802.1X), NA spoofing (SEND, RFC 3971, is the unused cryptographic fix).

## Transition and coexistence

| Mechanism | Idea |
|---|---|
| Dual stack | every node runs both; apps prefer IPv6 (Happy Eyeballs v2, RFC 8305 §3–5 [S15]: resolve both, start the AAAA connection first, start the A connection after a short delay, take whichever completes) |
| Tunnelling (6in4 proto 41, 6rd, Teredo/UDP) | IPv6 packets as payload of IPv4 across v4-only segments |
| Translation NAT64 + DNS64 | v6-only clients reach v4 servers: DNS64 synthesises AAAA `64:ff9b::a.b.c.d`, NAT64 translates headers; used by mobile carriers |
| 464XLAT, DS-Lite, MAP | carrier-side variants combining NAT64/NAT44 for IPv4-as-a-service over IPv6 access |

Current state: APNIC Labs measures **43.7 % of users IPv6-capable and 41.7 % IPv6-preferring worldwide** (2026-09-20) [S22]. IPv4 continues alongside indefinitely.

## Worked example: a host boots on a dual-stack LAN

MAC 02:00:00:00:00:01, router advertises 2001:db8:1::/64.

1. Link-local fe80::ff:fe00:1 (EUI-64) — DAD: NS to ff02::1:ff00:1 from ::, no answer → ok.
2. RS to ff02::2; RA arrives from fe80::1 with prefix 2001:db8:1::/64, A = 1, M = 0, RDNSS 2001:db8::53.
3. Global 2001:db8:1:0:ff:fe00:1 (+ a temporary privacy address for outbound), DAD again.
4. Default route `::/0 via fe80::1 dev eth0`.
5. To reach 2001:db8:1::99 (on-link): NS to ff02::1:ff00:99, NA back, frame to that MAC. To reach 2001:db8:9::1: same but for fe80::1 (router), then normal forwarding with hop limit decrement.

Ethernet destination MAC for an IPv6 multicast: 33:33 + low 32 bits of the group (ff02::1:ff00:99 → 33:33:ff:00:00:99). Switches with MLD snooping forward it only to interested ports.

## Pitfalls

- Payload Length excludes the header; a 40-byte header with Payload Length 0 is a legal (empty) packet.
- `::` at most once; `2001:db8::1::2` is invalid.
- A /64 is the smallest subnet for SLAAC (the IID is 64 bits, RFC 4291 §2.5.1); a /127 is not merely fine but *recommended* for inter-router point-to-point links (RFC 6164 [S15], which exists because a /64 there invites a neighbour-cache exhaustion attack).
- Link-local addresses are ambiguous without the interface (`%eth0`); default gateways in `ip -6 route` are usually link-local.
- Blocking all ICMPv6 breaks NDP and PMTUD → nothing works. RFC 4890 lists what must be allowed.
- IPv6 does not automatically "have no NAT": NAT66/NPTv6 exist, but the default and intent is global addresses with a stateful firewall.

## Exam-style questions

1. *Shorten 2001:0db8:0000:0000:0001:0000:0000:0001.* Two zero runs of length 2 → RFC 5952 §4.2.3 [S15] says the **leftmost** wins a tie: `2001:db8::1:0:0:1`. (§4.2.2 also forbids `::` for a *single* zero group, which is why `2001:db8:0:1:1:1:1:1` stays written out.)
2. *Give the solicited-node multicast address and its Ethernet MAC for 2001:db8::abcd:1234:5678.* ff02::1:ff34:5678 (RFC 4291 §2.7.1: the prefix ff02::1:ff00:0/104 plus the low 24 bits) [S13]; MAC 33:33:ff:34:56:78 (RFC 2464 §7: `33:33` plus the low **32** bits of the group) [S17].
3. *List three IPv4 header fields removed in IPv6 and why.* Header checksum (redundant with the L2 CRC and the mandatory L4 checksum, and costly because IPv4 forces a recomputation at every hop — see note 03); IHL and options (fixed 40-byte header, extension headers instead, RFC 8200 §4); fragmentation fields (routers never fragment, RFC 8200 §5; the Fragment extension header exists only for end hosts) [S13].
4. *How does a host learn its default router without DHCPv6?* From the Router Advertisement: the **source link-local address** of an RA carrying a nonzero Router Lifetime (RFC 4861 §6.3.4) [S13]. Note the consequence — even a network that uses stateful DHCPv6 for addresses still needs RAs, because DHCPv6 has no way to convey a default gateway.
5. *What does the A flag vs. the M flag in an RA cause?* A (on a prefix option): the host autoconfigures an address from that prefix (SLAAC); M: the host uses stateful DHCPv6 to obtain addresses. Both can be set.
