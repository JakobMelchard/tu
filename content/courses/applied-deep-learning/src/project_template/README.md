# Project skeleton for 194.077 Applied Deep Learning

Copy this folder, rename it, and fill in the placeholders. It encodes the three
assignments -- **Initiate**, **Hacking**, **Deliver** [S12, S13, S14] -- as
checklists so nothing is forgotten between October and the January
presentations. Official submission deadlines are announced in the preliminary
lecture (07.10.2026) and in ILEA/TUWEL; check them there and copy them into the
table at the bottom.

Two things to fix before you start, because they are graded and easy to get
wrong:

- **The repository must be named `<matriculation-number>_<subject-description>`**
  (e.g. `0828440_object-detection-of-pedestrians`), public or private with read
  access granted to the tutors [S12].
- **Nothing binary goes into Git** -- no datasets, no checkpoints. Use GitHub
  releases and fetch at runtime [S13]. `models/.gitignore` and `data/.gitignore`
  already do their part.

Assignment 2 links [`ashleve/lightning-hydra-template`](https://github.com/ashleve/lightning-hydra-template)
as a suitable structure [S13, S97]. This skeleton is a much smaller version of
the same idea; use whichever you prefer, but use one.

```
project/
  README.md              this file: problem statement, checklists, dates
  config.yaml            every hyperparameter and path in one place
  data/                  raw/ (never modified) and processed/ (regenerable); README with source + licence
  models/                checkpoints (git-ignored) and model definitions in models/__init__.py
  train.py               config -> data -> model -> optimiser -> loop with logging and checkpoints
  evaluate.py            fixed test set, metric(s), baseline comparison, error analysis dump
  report/outline.md      section skeleton for the technical report
  presentation/outline.md slide skeleton for the four-minute talk
```

Run from the repo root with the repo venv:

```
.venv/bin/python train.py --config config.yaml
.venv/bin/python evaluate.py --config config.yaml --checkpoint models/best.pt
```

## Problem statement (fill in during assignment 1)

- Task: <input> -> <output>, one sentence.
- Course topic used (at least one of CNN, RNN, deep RL, autoencoder/generative, transformer, GNN, XAI, LLM): <topic>.
- Project type (one of the four official ones [S12]): **bring your own data** / **bring your own method** / **beat the classics** / **beat the stars**.
- Metric: <name>, higher/lower is better, computed on <test split>.
- Success target: <value>, because <state of the art / baseline reasoning>.
- Data: <source, licence, size, how it is obtained without manual steps>.
- Compute budget: <hours on your own hardware -- the course provides none [S5]>, must fit in 45 h of programming time total.
- Work-breakdown structure with hours [S12]: dataset collection <h>; designing and building the network <h>; training and fine-tuning <h>; **building an application to present the results <h>**; writing the final report <h>; preparing the presentation <h>.

## Assignment 1 -- Initiate

- [ ] Problem statement above is filled in and one sentence long.
- [ ] Data is downloadable or generated by a script in `data/` (no manual clicks); licence noted.
- [ ] Data card: number of samples, class balance, input shape, known issues.
- [ ] Train / validation / test split is fixed by a seed and stored; the test split is not opened again until assignment 3.
- [ ] Learning-curve estimate: train a trivial model on 10 %, 30 %, 100 % of the data and check the metric still moves.
- [ ] State-of-the-art number found: paper, metric, split, preprocessing, and whether it is comparable.
- [ ] Trivial baseline computed (majority class / mean predictor / nearest neighbour).
- [ ] **At least two scientific papers** read and cited [S12].
- [ ] **Project type declared** (one of the four).
- [ ] **Work-breakdown structure with hours for all six buckets**, including building the demo application.
- [ ] Repository created with the required name and read access granted.
- [ ] Submission e-mail sent with the required subject line.
- [ ] Risks listed with a fallback for each.

## Assignment 2 -- Hacking

- [ ] `config.yaml` covers every knob; no magic numbers in code.
- [ ] `train.py` runs end to end on a 1 % subset in under a minute ("smoke test").
- [ ] Overfit-one-batch check passes (loss goes to ~0 on a single batch).
- [ ] Loss at initialisation is what it should be (e.g. $\ln C$ for $C$-class cross-entropy).
- [ ] Classical / small baseline trained and logged with the same pipeline.
- [ ] Main model trained; per-step loss, validation metric, LR and wall time logged.
- [ ] Checkpoints saved (best and last) with optimiser, scheduler, step and RNG state.
- [ ] Every run is reproducible from `config.yaml` + seed + git hash.
- [ ] At least 3 seeds for the headline configuration.
- [ ] **Error metric and its target value written down before the first training run** [S13].
- [ ] **Tests for pre- and post-processing exist and pass** (a training-loop test is optional and earns bonus points) [S13].
- [ ] CI green on every commit [S13].
- [ ] Python version stated and `requirements.txt` (or `uv`/Poetry/Pipenv) pinned [S13].
- [ ] Code auto-formatted with `ruff` or `black` [S13].
- [ ] No weights or datasets committed [S13].
- [ ] README states the metric, its target, the **achieved** value, and hours spent per WBS task.

## Assignment 3 -- Deliver

- [ ] Test set evaluated exactly once per final model; numbers frozen in `evaluate.py` output.
- [ ] Comparison table: trivial baseline, classical baseline, own model, state of the art (same metric, same split).
- [ ] Error analysis: confusion matrix or residual plot, the 20 worst errors inspected, slices by attribute.
- [ ] Ablation: remove the one ingredient you claim matters and show the drop.
- [ ] Limitations and what you would do with 10x compute.
- [ ] **Demo application** a stranger can run: CLI, Docker container, or an in-browser page with weights fetched from a GitHub release [S14]. It must run **without your GPU**.
- [ ] Report written from `report/outline.md`, **at most 5 pages**, one PDF, answering the four required questions, figures regenerable by scripts.
- [ ] Slides from `presentation/outline.md`, rehearsed with a timer, **under 4:00**; demo as an embedded screencast.
- [ ] Everything submitted **before the first presentation date** -- presenters are drawn at random [S5, S14].
- [ ] Repository is clean: README explains how to reproduce every number in the report.
